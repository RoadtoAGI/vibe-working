# CONSTRAINTS.md 模板

第一次在仓库运行闸门时，复制下方模板到仓库根目录（子工程放在其根目录），再按本仓库实际情况填写：

1. **命令**：换成本仓库真实可运行的测试、静态检查和覆盖率命令，每条都先运行一次确认可用。
2. **初值**：先用 `diff_metrics.py` 和变异工具测一次基线。下表的初值依据：圈复杂度 10 是 McCabe 的经典建议；CRAP 30 是 Crap4j 的默认阈值；改动行覆盖率 80%、变异杀死率 60% 取自 addyosmani/agent-skills 的 constraint-driven-development。这些阈值只约束本次改动涉及的代码。基线已经明显低于初值时，按基线设定阈值，同时把初值写进"只记录"，作为收紧的目标。
3. **运行时机**：耗时以秒计的检查标为"每次交付"，由实现方在交付前运行；变异测试这类耗时较长的检查标为"质量闸门"。
4. **路径**：`<闸门脚本>` 指本 skill 的 `scripts/` 目录，按当前加载的技能安装目录定位。`<起点>` 由执行方填入：交付前自查时是本次执行开始时记下的提交，闸门中是审查范围的起点。

````markdown
# 质量约束

本文件约定这个仓库的交付证据，实现方不得为通过检查而修改它。阈值只升不降；下调阈值或新增例外由用户或质量闸门的审查方写入，并注明理由与到期日。

## 底线

- 不为通过检查删除或放宽断言、跳过测试、删除测试文件
- 不新增屏蔽注释（noqa、type: ignore、eslint-disable、nolint、pragma: no cover / no mutate 等）；确有必要时登记到下方例外
- 不提交未实现的桩、空异常处理，也不把失败改成静默返回默认值
- 不提交密钥

## 阈值

| 维度 | 规则 | 检查命令 | 运行时机 |
|---|---|---|---|
| 单元测试 | 全部通过 | `pytest -q` | 每次交付 |
| 静态检查 | 无错误 | `ruff check .` | 每次交付 |
| 验收场景 | 全部通过 | `pytest tests/acceptance -q` | 每次交付 |
| 改动行覆盖率 | ≥ 80% | `pytest --cov=<包> --cov-report=json:tmp/quality-gate/coverage.json -q && uv run --no-project --with lizard python3 <闸门脚本>/diff_metrics.py --base <起点> --coverage tmp/quality-gate/coverage.json --min-changed-coverage 80 --ccn 10 --crap 30` | 每次交付 |
| 改动函数圈复杂度 | ≤ 10 | 同上一行 | 每次交付 |
| 改动函数 CRAP | ≤ 30 | 同上一行 | 每次交付 |
| 防削弱 | 线索逐条有合理解释 | `python3 <闸门脚本>/floor_guard.py --base <起点>` | 每次交付 |
| 改动代码变异杀死率 | ≥ 60%（不计等价变异体） | `mutmut run && mutmut export-cicd-stats` | 质量闸门 |

|---|---|---|---|---|
````
