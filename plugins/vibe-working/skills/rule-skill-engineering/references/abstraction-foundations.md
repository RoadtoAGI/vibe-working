# 归并与抽象的理论依据

本文件供规则开发者和审阅者追溯方法依据、解释关系判断或考虑跨领域迁移。操作判据由 [SKILL.md](../SKILL.md#归并抽象与职责) 维护；这里说明研究支持什么，以及本 skill 如何使用这些思想。

## 目标、机制与关系

| 研究 | 来源支持的命题 | 对规则工程的用途 |
|---|---|---|
| [Gentner，1983：结构映射](https://onlinelibrary.wiley.com/doi/10.1207/s15516709cog0702_3) | 类比可以映射对象之间的关系；由高阶关系组织的连贯结构具有系统性 | 比较与当前目标相关的关系结构，发现表面不同的规则或案例共享的机制 |
| [Mitchell、Keller 与 Kedar-Cabelli，1986：解释型泛化](https://link.springer.com/article/10.1023/A:1022691120807) | 利用领域知识解释实例为何满足目标概念，再概括使解释成立的条件 | 抽象保留对结果有作用的条件，区分案例载体与可迁移机制 |
| [DeJong 与 Mooney，1986：解释型学习](https://www.cs.utexas.edu/~ml/papers/ebl-mlj-86.pdf) | 讨论概括解释所得充分条件的边界；可操作性与执行系统已有能力相关，并可随能力变化 | 保留替代实现，依据执行者的知识与能力选择规则粒度 |
| [van Lamsweerde，2001：目标导向需求工程](https://webperso.info.ucl.ac.be/~avl/files/RE01.pdf) | Why 可用于寻找上位目标，How 可用于细化；AND/OR 关系区分共同满足与替代实现；目标还需关联责任和操作 | 连接目的、实现与责任，区分子要求之间的配合和替代关系 |
| [Parnas，1972：模块分解](https://www.cs.lafayette.edu/~gexia/cs301/resources/parnas.html)（[正式 DOI](https://doi.org/10.1145/361598.361623)） | 模块围绕需要封装的设计决策划分；层级依据明确关系建立，模块分解质量与层级结构分别判断 | 用独立职责和变化边界判断 skill 拆分，用实际关系解释层级 |
| [Ganter、Rudolph 与 Stumme，2019：形式概念分析](https://iccl.inf.tu-dresden.de/w/images/4/49/IntroFCA-RW2019.pdf) | 形式概念由对象集合及其共有属性定义；一般与具体按包含关系组织，允许交叉的概念关系 | 区分共同上位概念、特化与等价，允许多个任务入口引用同一规则 |

这些研究提供关系比较、目标细化和概念组织的依据。本 skill 将其用于自然语言规则与 agent 协作，是结合执行者和消费者作出的工程设计。形式概念中的属性选择、领域解释中的前提，以及自然语言规定的等价性，仍需相应领域知识和实际语义判断。

## 目的解释与机制解释

目标说明期望得到什么，机制说明哪些关系和条件促成该结果。例如，要求读者能够理解当前危险，是交付目的；通过人物所知与信息释放建立这种理解，是可能的实现机制。作者授权与内容边界按其权威成立。

从已有方法追问目的，可以找到共同目标；解释方法为何起作用，可以找到共同机制；对照条件、允许行为和结果，才进入等价判断。语义不同的方法可以共同服务同一目标，具体情境决定它们是配合、替代还是分别适用。

## 推导与迁移的范围

领域理论可以自上而下指导规则推导，案例可以自下而上帮助发现、修正和具体化机制。解释应保留使关系成立的条件；依赖某个故事、设备或执行环境的条件继续保留相应作用域。

解释型学习中的一条证明或方案通常只给出实现目标的一组充分条件。将其迁移到开放任务时，方案可以作为策略；是否成为必要步骤，仍由任务要求、不可替代的依赖或具体风险决定。创作与专业判断可以通过案例和产物辨别效果，形式证明适用于已经明确形式化的命题。

WWWH 在本 skill 中是 Why / What / When / How 的分析简称。KAOS 为 Why/How 的目标抽象与细化提供直接依据；[W6H 需求询问研究](https://arxiv.org/abs/1508.01954)提供以问题维度获取信息的相关思路。两者分别保留各自术语与用途，本 skill 将问题维度用于按需对齐，未将 WWWH 作为统一的软件工程标准或固定工作流。
