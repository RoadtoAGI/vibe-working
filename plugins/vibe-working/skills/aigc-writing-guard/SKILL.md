# AIGC Writing Guard

在生成前预防、在已有文本中诊断和修订 AI 口癖，让读者顺着文本就能理解对象、关系和解释顺序。治理单位是有上下文的表达功能，不是词；词表只负责定位，是否为问题由阅读决定。目标是在原意和任务约束内写出更清楚、准确、自然的表述，减少口癖服务于这个目标。

## 任务入口

| 任务 | 做法 |
|---|---|
| 生成时预防 | 起草或改写时遵守下文的共同约束与判断方式。任务明确涉及某类口癖，或反馈显示同类问题反复出现时，起草前读取对应的 [语义模式](references/semantic-families.md) 与当前语言的判据页；需要可复制提示时读 [prompt 契约](references/prompt-contracts.md)。按原任务交付正文 |
| 专项审阅 | 用户要求审查 AI 表达，或反复修订仍有同类问题时，按 [口癖图谱](#口癖图谱) 诊断实际文本。需要批量定位候选时运行 [lint](#表层定位)，先后顺序由诊断需要决定 |
| 修订与润色 | 按获准范围阅读并改进文本；已有 findings 帮助定位，不代替范围内的阅读。只修指定问题时处理对应表达及受影响的衔接。每处改动按 [阅读保真](#阅读保真) 比较改稿 |

整篇或整节任务覆盖范围内的正文和各级标题（含 Markdown、LaTeX 标题文字）；局部任务处理指定内容及受影响的衔接，周边内容提供语境。修改保持标记语法、标签和用户锁定的原词。

领域边界：学术稿的主张力度、定位对比、Limitations 和结果解释由当前环境的 `academic-writing` 维护，英文语法与学科精确性也归它；需要论文表达示范时按 [论文参考消费](references/academic-exemplar-library.md) 取用已有片段或参考库。商业写作不推断来源、指标或行业基线。日常、医学等非代码正文检查是否被写成代码设计文档或执行记录，见 [代码文档语域](references/code-document-register.md)。

## 共同约束

生成、审阅和修订均保留已有事实、数字、公式、引用、专名、必要限定及作者结论强度，遵守任务范围和格式要求。新增内容依据已有材料；缺少输入时保留原状态，必要时在工作记录中说明。要求冲突时按顺序让步：保留信息与确定度，遵守任务范围与文体，匹配作者声音，最后才处理具体口癖。

### 阅读保真

写作与修订以读者能够沿文本理解内容为完成条件。保留、删减、补足与重组都可以是合适选择，依据其对理解、精度和自然表达的实际作用判断。在修改处连同必要的前后文检查：

- **对象与回指**：主语、宾语、比较双方和量的单位清楚；必要复现、代词和连接词帮助读者追踪对象与关系，省略须让读者就近、明确地还原所指。
- **关系与顺序**：承接、因果、转折、举例和总结的作用完整，按读者的理解依赖安排信息。具体解释需要借助前文的共同关系才能接上时，保留或补明这一承接；删掉套式后，用已有材料重新表达它原本承担的有效功能。
- **语言与导航**：用目标语言的自然搭配和稳定术语。标题结合所辖内容及父级、同级语境提示主题与范围，上位概括保留检索所需的区别。

以修订前后的连续句段比较这些功能，判断改稿具体改善了什么。有前轮修订记录或作者裁定时，前轮已接通的承接和已统一的术语也在比较范围内。字数缩短、命中减少或句法正确都不能抵销衔接、解释或导航的退化；发生退化时恢复被删成分或重组受影响表达。审阅原稿时也识别范围内的衔接缺口；只有对照能支持时才判断问题由治理引入。准备压缩解释、合并或拆分相邻句、改写回指、展开抽象概念或调整承接顺序时，先读 [修订案例](references/semantic-families.md#阅读功能的修订示例)。

### 结论保真 `unrequested_claim_weakening`

- **触发**：生成或润色把作者已有的明确结论、具体判断或研究解释改成猜测、含糊倾向或额外自我限定，且作者未要求这种改动。
- **动作**：根据已有文字、材料和作者解释恢复原意及结论力度，删除模型自行添加的缓和；审阅任务指出具体改动，修订任务在获准范围内恢复。
- **验收**：结论的确定性、对象和含义保持；原文已有的限定与不确定性保留，作者明确要求的调整按其要求执行。
- **强度**：hard_constraint，依据作者对内容及结论力度的控制权。

## 词表定位，语感裁决

每条规则的触发写的是问题，不是词形。看到候选先问：

1. **删除**：删掉这个词、半句或并列项，信息、关系与确定度是否不变？不变，它在凑数。
2. **替换**：换成最朴素的说法（是、有、没有、还没、也、都），是否更顺且不失精度？是，就换。
3. **归属**：这个评价、被否定的选项、被反驳的看法，读者能在文中找到它的标准、主张者或内容吗？找不到，它是姿态。
4. **朗读**：本领域的明白人会这样说吗？公文味、讲师腔、审计腔都是答“不会”的信号。
5. **迁移**：改完是否只换了同功能的另一个口癖，或删后留下比原文更泛的命题？

一处命中按“细心的作者会不会故意这样写”衡量：单个书面词、一次三项并列、一个破折号不是问题，成片才是。结构与姿态上的习惯比词更稳定，先看段落在做什么（铺垫、宣告、否定衬托、罗列代替判断），再看词。改写按段落恢复作者的口吻，不为显得自然而加口语填充、感叹或第二人称；清楚的原文直接保留，改写须能说出理解、精度、搭配或导航上的具体收益。不以 lint 命中数或自拟“AI 率”代替判断。

## 口癖图谱

语义模式分四组，完整的触发、动作、边界与强度见 [高级语义模式](references/semantic-families.md)。按文本呈现的问题选入口，不要求依次扫描：

| 组 | 共同机制 | 子模式 |
|---|---|---|
| [信息冗余](references/semantic-families.md#信息冗余) | 删除后信息及理解功能均不减少 | 表演式前缀；命题表演（宣告重要、显然、本质，任务话语泄漏）；语义复读；其他冗余 |
| [语义指向](references/semantic-families.md#语义指向) | 读者无法从词恢复对象、来源或关系 | 抽象名词与空泛评价（能力、机制；清晰、有效、robust）；模糊归因；比喻失配 |
| [论证姿态](references/semantic-families.md#论证姿态) | 制造文中不存在的对立面来衬托结论 | 否定转折骨架（不是 X 而是 Y、not X but Y）；虚设对手（有人认为、Many believe） |
| [文体组织](references/semantic-families.md#文体组织) | 形式与语域不服务内容和体裁 | 模板对称；并列罗列代替判断（X 与 Y）；章节标题套式；书面腔与虚词堆叠（尚未、亦、进行；serves as）；代码文档语域跨域 |

同一功能问题按决定修订动作的具体模式报告一次：表演式前缀归 `performative_preface`，任务话语泄漏归 `meta_performance`，标题导航问题归 `formulaic_heading`，正文并列归 `hollow_coordination`，语域错位归 `code_document_register_leakage` 或 `stiff_register`。上位原则只解释原因；尚不能归入具体模式的冗余由 `low_information_density` 承接。仅换词、同类问题复发或用户要求比较时，用 [同功能迁移](references/semantic-families.md#同功能迁移-semantic_function_migration) 检查改稿。

## 表层定位

以本 skill 目录为工作目录运行，输入路径按实际位置提供：

```bash
python3 scripts/aigc_style_lint.py INPUT.md
python3 scripts/aigc_style_lint.py INPUT.md --lang zh --format json
cat INPUT.md | python3 scripts/aigc_style_lint.py --lang auto --format json
```

默认 `--lang auto` 按可见文字选择词库，混排时两种都跑。每条命中是复核候选，`message` 写的是该候选该问的问题；成片才有意义的词项只在整篇达到下限时报告。脚本只完成表层扫描，零命中只说明未发现已注册信号，完整审阅结论必须有实际阅读支持。字段含义、退出码与自定义词库见 [lint 接口](references/lint-interface.md)。

## 修订纪律

- AI 自己撰写的正文禁止无功能的自我标注和任务话语泄漏；删除框架，保留其中有效的背景、目的或承接，从实际内容开始。
- 直接陈述核心判断、对象和成立条件。被否定的选项、被反驳的看法在文中有归属时保留并写全；没有归属就删去引子。连接词、必要复现和真实比较承担理解功能时保留。
- 删除、补足和调序都是可用方法，依据材料和阅读需要选择：句子问题连同上下文修句子，跨段问题处理段落关系，章节缺少中心时在授权范围内调整结构。
- 标题从所辖内容提炼对象、问题、关系或功能，结论从正文读出来；保留读者会检索的编号、术语和固定搭配；只换连词不算修复。命名取舍难以判断时读 [标题判据](references/semantic-families.md#章节标题套式-formulaic_heading) 与当前语言的真实改稿对。
- 换词可以修复具体的搭配或指代失配；空泛功能仍在的近义替换（清晰→明确、尚未→仍未、不是 X 而是 Y→Y 而非 X）继续处理。修订后复读受影响的完整段落及必要相邻段。
- 交付范围跟随用户任务；未解决问题影响成稿时说明。

## 内容保护与交付

用户原文按获准修改范围处理；逐字引文、语言分析对象和代码数据中的同形字符串按其实际用途保护，保护只覆盖相应片段。各模式的触发由有害的表达功能界定：字面技术含义、准确压缩、必要条件和结构导航按用途判断，承担有效功能的表达不因同形命中成为问题。

普通生成或修订直接交付正文，必要时简述实质改动或未解决事项。专项审阅用原文位置或短引指出问题，说明它妨碍了什么理解，并给出修订方向；自然语言足以说明的判断无需固定字段。自动化消费者或用户明确要求结构化报告时，使用 lint 接口中的字段；未执行的检查不声称完成，不判断作者身份或 AI 概率。

## 验证

修改脚本或词库后运行 [lint 接口](references/lint-interface.md#开发检查) 中列出的检查；普通写作无需运行。自测核对既有中文行为、有来源的中英文真实句子和机械检测的坐标与接口；这些参与过开发的来源不充当独立效果证据。词库新增条目遵循 [更新规则](references/code-document-register.md#更新规则)：写清字面功能、失配成立条件和改写收益，用相邻正常用法检验触发范围。
