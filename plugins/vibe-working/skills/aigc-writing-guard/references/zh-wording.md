# 中文判据与真实改稿对

处理中文文本时读取本页。语义机制、动作与强度由 [高级语义模式](semantic-families.md) 定义；本页只补中文专属的词项、语感判据和真实改稿对。表层候选由 [中文模式库](zh-patterns.json) 定位。

案例全部来自本机真实改稿与用户裁决：2026-10-10 讲义标题去罗列、2026-10-09 可视化站点文案清理、2026-09-26 Agent 讲义润色，以及记录在 study 项目记忆中的用户反馈。给出改后文本的，改后文本就是实际采用稿；只给原句的，是待判断的观察，本页只提出问题，不自拟改法。

## 词表定位，语感裁决

中文没有词边界，命中更依赖语境：单字“则、并、即、均、系”不进词表，“有效、清晰”同形于术语。词表给出位置，是否为问题由下面的问题决定：

1. **删除**：删掉这个词或半句，信息、关系与确定度是否不变？不变，它在凑数。
2. **替换**：换成最朴素的说法（是、有、没有、还没、也、都、就），是否更顺且不失精度？是，就换。
3. **归属**：这个评价、对立面或并列项，读者能在文中找到它的所指、主张者或内容吗？
4. **朗读**：本领域的明白人会这样说吗？公文味、讲师腔、审计腔都是答“不会”的信号。
5. **迁移**：改完是否只换了同功能的另一个口癖（尚未→仍未、清晰→明确、不是 X 而是 Y→Y 而非 X）？

冲突时按顺序让步：保留信息与确定度，遵守任务范围与文体，匹配作者声音，最后才处理具体口癖。一句里一个书面词不是问题，一页里成片才是；命中按“细心的作者会不会故意这样写”衡量。

## 书面腔与虚词

用户 2026-10-10 指出“未”是典型虚词。它本身合法，问题在于模型把半公文、半文言的否定词与轻动词当作默认语域，讲义、说明和随笔读起来像通知。判断看密度与体裁的落差，不按单词计数。

| 书面腔 | 朴素说法 | 保留条件 |
|---|---|---|
| 尚未、未能、并未、未被、未经、仍未、均未 | 还没、没能、没有、没被、没经过 | 词是术语的一部分：未定义行为、未读消息、尚未提交的事务；法律、公文、学术摘要 |
| 亦、皆、乃、均、则 | 也、都、是、就 | 数学与规则条文里的“若……则……”；引文 |
| 予以、加以、进行、得以、有所、作出 | 直接用动词：检查、测试、改进、能、有、做 | 公文固定搭配（予以受理、进行公示）；名词已是术语（增量编译、执行计划生成） |
| 旨在、基于、围绕、聚焦、通过……来…… | 为了、按、针对；直接写方法 | 术语与接口名 |
| 作为、充当、被视为、扮演……角色 | 是、有、就是 | 真实的角色或职能表述 |

**真实改稿对**（可视化站点文案，2026-10-09，用户要求清理 AI 口癖后由模型改、用户验收）：

| 改前 | 改后 |
|---|---|
| 尚未处理完的课程数量 | 还没出队的课程数 |
| 尚未处理的原区间位置 | 下一个待检查的原区间 |
| 未取得回执，须重跑/查询 | 没有回执，要重跑或查询 |
| 返回 interrupted，本条消息未处理。 | 返回 interrupted，这条消息没有执行。 |
| 已经进行的传播层数 | 已经传播的层数 |
| map 记录 int 与输入序列，按需转换；numbers 尚未取值。 | map 只记下 int 和 parts，取值时才逐个转换；此刻还没有转换任何字段。 |
| Telegram 适配器没有未知发送核对能力；拒绝盲重放。 | Telegram 适配器无法核对发送结果，所以不盲目重发。 |

同一批改稿保留了 `1061109567 是尚未到达的哨兵值，不代表实际票价` 里的“尚未”，只把“不代表”改成“不是”：这里“尚未到达”读来自然，改它没有收益。

Agent 讲义润色（2026-09-26）里的同类修复：`具体官方来源、完整性与对应发行版本尚未得到完整认证` → `来源、完整性和对应的发行版本都无法确认`；`分布式运行本身没有承诺持久队列或副作用去重` → `分布式运行时解决的是跨进程运行与通信，本身不提供持久队列或副作用去重`。后一例换掉的不只是“承诺”，还补上了主语真正做的事。

### 审计腔与执行话语

用户 2026-09-26 指出 Codex 写的讲义带“审计腔”：“需要核对、分别检查、另行核实”出现在讲解正文里，像执行报告而不是讲义。同类还有对读者称“你的 X”、每篇末尾的“见下一篇”导航句、“这件事”作万能指代（用户 2026-07-12 在 nn 讲义里一轮清出 43 处）。

| 改前 | 改后 |
|---|---|
| 其工作区基线有产品规则，审查任务应显式核对提交或补丁位置。 | 新 worktree 从哪个版本检出由产品规则决定，所以审查任务要在委派说明里写明提交或补丁位置。 |
| 你的 **OranClaw** 对应执行框架这一层：将模型提出的动作交给工具，再把真实结果带回后续判断。 | **OranClaw** 的执行框架实现的也是这个循环：把模型提出的动作交给工具执行，再把真实的结果带回下一轮判断。 |

修法不是删掉“核对”二字，而是把被审计腔遮住的关系写出来：谁决定、所以要做什么。“这件事”换成具体所指（这笔账、这个结果、这套级联），或者直接删，让引号短语当主语。

## 空词：评价代替属性

用户 2026-10-10 指出形容词性的“清”（清晰、清楚）是空词。空词断言一种品质，句中却没有可核对的标准：清晰相对什么？不清晰会是什么样？答不出来，词只是在替读者加音量。常见的还有明确、有效、高效、全面、系统、深入、合理、科学、显著、良好、强大、丰富、灵活、扎实、精准、稳健、完善，以及抽象名词能力、机制、体系、维度、层面、价值、意义。

**真实改稿对**：

| 改前 | 改后 | 发生了什么 |
|---|---|---|
| 本轮有效输入仍为 10,000 Token。 | 模型处理的输入仍是 10,000 Token，只是其中 8,000 复用了已有计算。 | “有效”被它实际指的事替换 |
| 不同机制保存的信息决定恢复能力： | 保存了什么，决定了能恢复到什么程度： | 两个抽象名词换成读者能检验的问句 |
| 有效括号与动态规划 | 按结尾位置递推有效括号长度 | “有效括号”是术语，保留；空的是罗列 |
| 各系统的计数单位 | 各系统的“一轮”各数什么 | 抽象名词换成本页真正比较的东西 |
| Prepare：沿同一列查看四套系统。 | Prepare 列：进入循环前各系统准备什么；Hermes 在这之前先过回合租约，OpenClaw 先过车道和写入权。 | 六条同模板图注各自写出所辖内容 |

**待判断的观察**（study 讲义原句，均为模型所写）：

- `1:1 配对的收益是清晰的隔离边界：每个 server 的会话状态、能力清单、连接……` 冒号后已经列出边界是什么，“清晰的”删去不损失信息。
- `确保其在与用户交互时能够高效、清晰地完成任务` 高效相对什么？清晰相对什么？句中没有标准，两个词都是音量。
- `目标清晰、成本可控、业务对接方便` 三个评价并列，没有对象；如果材料里有目标是什么、成本多少，写它们。
- `组合收益来自责任清晰：LLM 负责解释候选内容，人负责确认，应用维护归属` 评价词后面紧跟兑现它的清单，这种写法可以保留，也可以只留清单。

判断“清晰”时先看它后面有没有被兑现。兑现了，评价词可留可删；没兑现，补兑现或删评价。不用“明确”替换“清晰”。

## 并列罗列：罗列代替判断

用户 2026-10-09 提出标题不用“XX 与 XX”并列命名，要点出主旨或核心问题；2026-10-10 的交接文档把判断写清：并列本身没有问题，问题是用罗列代替判断。标题只说本节里有哪些东西，不说本节对这些东西得出了什么；作者从正文挑几个显眼的名词用“与”接起来，就不必表态。模型批量起标题时这是最省力的路径，所以常成片出现。

判断时问一件事：这个“与”在替读者做事，还是在替作者躲判断。正文若在 A 和 B 之间建立了关系（一个决定另一个、一个不等于另一个、一个是另一个的条件或后果），标题只把两者并排，读者就得自己去正文找。同一篇里每节都长成“主题：A 与 B”时，目录上也分不出各节讲什么。

标题要做到的事：说出本节的判断，结论从正文读出来；保留检索把手（知识点编号、术语、业界固定搭配）；概括到能区分同级为止；并列项本身是内容时可以留；对比句只在该区分就是本节论点时用。只把“与”换成“和、及、、、/”或冒号不算改好。

**负例**（讲义中的真实标题，摘自交接文档）：

| 标题 | 掩盖了什么 |
|---|---|
| 评估与运行优化 | 两个不相干的主题装进一个文件名，既没说评估什么，也没说优化什么 |
| 质量与生产：观测、测试、评估与防护 | 主副标题六个抽象词，没有对象，任何系统的任何章都能套 |
| 上下文工具与执行隔离 | 三个名词拼接，谁隔离谁、为什么，没有交代 |
| 汇总与讲解 | 两个动作词描述的是作者做了什么，不是内容是什么 |
| 二、核心机制与代码入口（两篇讲义同名） | 同一个抽象模板，目录里分不出是哪个系统的什么机制 |
| TRAIN-10 训练与验证：质量、成本与失败诊断 | 三个抽象维度，没有本节的判断 |
| 章节导航：并行、数学与应用 / 章节导航：设计方法与图算法 | 导航标题本可保留，但两条同模板、各自只是章名清单，没有给读者选路的线索 |

**真实改稿对**（2026-10-10 采用稿；多数由模型按正文提案、用户验收）：

| 改前 | 改后 | 判断 |
|---|---|---|
| FLOW-04 检查点：恢复点与外部副作用 | FLOW-04 检查点：能续跑，不保证外部调用只发生一次 | 正文第二段的结论进了标题 |
| SYS-05 TCP：可靠字节流与连接状态 | SYS-05 TCP：字节送达不等于业务提交 | 对比句成立：这条区分就是本节论点 |
| PY-07 事件循环：协程、Task 与 Future | PY-07 事件循环：await 让出执行权，不会自动并发 | 三个术语的关系写成一句判断 |
| DB-07 并发写入：条件更新、锁与唯一约束 | DB-07 并发写入：把不变量交给数据库保证 | 三种手段的共同点 |
| DIST-12 持久化与高可用：RDB、AOF、复制和分片 | DIST-12 持久化与高可用：每种机制会丢什么 | 四个名词保留在正文，标题给读者要带走的问题 |
| COMM-03 推送方式：轮询、长轮询、SSE、WebSocket 与 Webhook | COMM-03 推送方式：从轮询到 Webhook，按谁收事件来选 | 首尾检索词保留，中间换成选择依据 |
| 七、边界与常见误解 | 七、常见误解：三条关于 decoder-only 的误读 | 对手有了对象和数量 |
| 二、核心机制与代码入口 | 二、源码索引：从 create_agent 到 Pregel 的函数入口 | “从 A 到 B”这里有具体对象，不是模板 |
| 07｜AlexNet：数据、算力与技巧合流 | 07｜AlexNet：旧方法为什么到 2012 年才奏效 | 问句成立：正文回答了它 |
| 章节导航：分析、排序与数据结构 | 章节导航：基础，先学代价分析和数据组织 | 三条导航用首词区分 |
| # Agent 任务编排：从业务流程到反馈循环 | # Agent 任务编排 | 副标题是“从 A 到 B”模板，删去不损失（2026-09-26） |

**用户或审核保留的标题**，说明边界：`回溯：撤销、去重与剪枝`（三项各有一个 H3，新标题只覆盖其一）；`二、条件速查：成员、包含与非空`（速查表，列出的三种条件即内容）；`十三、常驻样本：OpenClaw、Hermes 与托管 Agent`（三个产品名即内容）；`递归：子问题、调用顺序与状态`（三项即本篇三个 H2，提案只换了连词）；`缓存故障：穿透、击穿与雪崩`（业界固定说法）；`测试与代码质量审查`（用户定的文件名，模型改过后用户改回）。提案 `1. OranMemory：应掌握哪些输入、状态和输出` 被否，原因是原标题已是问题，新标题是否定对比句且只覆盖一个小节。

正文里的并列同理。可视化站点页面目标 `观察消息怎样重发、调用怎样配对，以及测试与审批怎样决定交付。` 改为 `模型不记得上一次调用，程序怎样把历史和工具结果拼进下一次请求；内层循环交回补丁后，测试与审批怎样决定能否交付；各系统的“一轮”各数什么。`——并列项没有减少，但每一项都带上了本页要回答的问题。`让同一条消息走过四套骨架，比较准入、循环、保存与交付。` 改为 `四个系统各为什么场景而造；同一条消息在它们里面怎样被接纳、循环、保存和送达；遇到一项任务该选哪一个。`

## 否定转折与虚设对手

用户 2026-07-12 在 nn 讲义正文里点名 `这不是程序员的能力问题` 作为反例，要求清除“X 不是 Y，是 Z”“重点不在 X 而在 Y”“归根结底”“其实是 / 本质上是”“真正的 X 是 Y”这一族句式，包括作为人物内心独白出现的同一模式；该项目的规则把它列为硬禁。允许的例外用户也说了：“理论上……实际上……”的实指对比，“必要条件，不是充分条件”这类精确逻辑表述。标题去罗列时的裁决一致：对比句只在区分本身就是本节论点时用（`字节送达不等于业务提交`、`可见不等于原子` 被采用），只为显得有力的不用。

**待判断的观察**（study 讲义原句）：

- `这些模型真正值得学习的不是名字，而是它们在 "token 来源 / 模态融合位置……"` 谁主张学名字？找不到，前半句是衬托。
- `扩展的做法几乎都不是"从头训一个长上下文模型"，而是一系列工程技巧的组合` 读者可能默认长上下文靠重训，前半句纠正了一个真会有的假设，骨架成立。这类句子一篇一两处可以，成片就是模板。
- `所以 encoder-only 不是被取代，而是和 decoder-only 形成了分工` “被取代”是流传很广的看法，对手真实，保留。
- `很多人以为"模型调用函数"，好像模型真的执行了你的 Java 方法` 这个“很多人”能指认吗？能，写出是谁或在什么场合这样以为；不能，直接写模型不执行函数这一事实。
- `直觉上，多出来的 36 层至少可以学成"什么都不做"，让 56 层网络至少不输给 20 层网络` 这是 ResNet 论文自己提出并用实验推翻的直觉，直觉就是材料，保留。
- `表面上看，Claude Code 只是多了一组 mcp__computer-use__* 工具` 随后正文给出会话级 runtime 的差异，“表面上看”引出的是作者要纠正的读法；若读者并不会这样看，引子可删，直接写差异。

区分真实对手与衬托的办法只有一个：去找。文献、前文、用户确认过的常见误解都算；“某些人、有些人”找不到出处就是在造对象。
