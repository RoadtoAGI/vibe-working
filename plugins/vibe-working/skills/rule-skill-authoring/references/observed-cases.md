# 开发观察案例：规则落实的失效形态

本文件收集实际开发中观察到的规则失效与修复，供[SKILL.md](../SKILL.md#规则落实让规则进入执行者的决定)的"规则落实"一节在诊断时参照。每条案例保留原情境、决定性差异与迁移边界，并给出来源定位。它们是开发证据，不是留出评测：案例说明某种失效形态确实发生过，不证明对应规则在未展示任务上稳定奏效。

案例去掉项目名称和具体领域后仍成立的部分，才是可迁移的机制；具体人物、字段名和数字只用于定位来源。

## 1. 规则强度递增，行为不随之改善

**观察**：一条"普通操作不逐项呈现"的写作规则，在五轮迭代中逐步加强：先补判据，再区分事实与呈现义务，再加跨题材正负例，最后明确禁止迁移备注。执行模型在第四轮删掉了多余动作，第五轮在更明确的规则下重新生成同一动作，并在最终回复中宣称"已按要求省略"。

**决定性差异**：规则文本已经没有歧义，失效来自模型未稳定执行已读取的语义规则，以及自评与产物不一致。继续追加禁词、字段、案例或检查环节只会扩大提示词与流程。当时的裁决是停止堆叠，保留通用语义与一组跨题材正负例，把动态效果标记为未通过。

**迁移边界**：本例不说明规则无用，只说明"强度递增而行为不单调改善"是换方向的信号：去查加载、输入、能力或上游是否已把决定写死。规则本身仍有歧义时，先修规则。

来源：`MUSE/docs/Level_2_architecture/pipeline/2026-08-30-Query183生成对照与流程膨胀.md` §7。

## 2. 规则内部矛盾，执行者选"更保险"的一条

**观察**：同一份写作规则里，一处要求"必须呈现这条任务的结果，不能省略"、"完整解释加行动验证"，另一处要求"不把任务清单当 checklist 逐条交付"、"禁止平铺同等密度"。产物呈现为逐项结算的流水账；审阅侧的句级判据又识别不出段级的低读者收益。

**决定性差异**：两条规则在同一情境下冲突，模型选择了更保险的"完整呈现"。修复落在规则正文：删除冲突条款，把"省略"写成默认值，呈现义务改为按戏剧代价判断；审阅判据从句级上提到段级。

**迁移边界**：规则冲突表现为执行者的系统性偏向，而非随机失误。看到执行者稳定选择某一侧时，先查是否存在反向要求，再考虑是否是能力问题。

来源：`MUSE/docs/Level_2_architecture/pipeline/2026-05-19-流水账治理-协议规则双修.md` §1.3。

## 3. 声明了消费者，没有人读取

**观察**：设计阶段的 schema 为关键场景规定了一个"转折方向"字段，并声明由编排、角色切片与审阅三方消费。真实产物中该字段普遍被填写；两包渲染脚本都不输出它，执行协议不读取也不传递，审阅只把它列为不应出现在正文的设计词。此前一次覆盖审计按 schema 的声明判定"符合现有分工"。

**决定性差异**：声明存在被当成链路存在。设计成本已经付出，写正文的执行者却拿不到这条信息。修复在渲染器和消费者两端接线，或停止产出该字段；两者都比继续填写合理。

**迁移边界**：核对"谁读这个字段"要沿渲染脚本、派发输入和消费者正文取证，不以 schema 注释为准。字段有产出、无读取，是过度设计的直接证据。

来源：`MUSE/docs/Level_3_implementation/skills-audit/2026-09-17-skill-rule-grounding-audit.md` F1。

## 4. 转换器把旧语义送进热路径，同类断点只修一处

**观察**：设计产物到写作者视图的渲染脚本，把已被撤销的"以物代解释"前提作为字段说明输出，把其他扩展字段以英文键和原始枚举输出，写作者的规则里没有这些键的含义。更早一次对照已指出"旧语义仍通过渲染器进入正文热路径"，当时只修了世界观披露一节，同一函数中的其余字段没有检查。

**决定性差异**：转换器是热路径的一部分；消费者读到的是转换后的版本，不是源规则。同类断点只修被举报的一处，是打地鼠式修复。修复应逐字段处理渲染器：保留的字段渲染为消费者能理解的说明，枚举映射为短语，已撤销语义删除。

**迁移边界**：任何摘要、提取、模板渲染、字段映射都可能把目的改写成动作或留下旧语义。规则更新后，沿转换链检查消费者实际读到什么；同一函数内的同类字段一次修全。

来源：同上 F2；`MUSE/docs/Level_2_architecture/pipeline/2026-08-30-Query183生成对照与流程膨胀.md` §4.3。

## 5. 模型自拟示例替换为真实观察

**观察**：方法规定案例只能从实际观察提炼后，运行技能中仍有二十余处由撰写者自拟的示例，部分直接标明"构造"。同一机制的真实材料已经存在于行为对照记录中：被否决的逐项清单原句、自证式展开的原句，以及实际改变资源与出口的正例原句。

**决定性差异**：自拟示例反映撰写者对规则的理解，可能复现待修正的误读；真实原句还能让作者直接核对判断是否成立。处置分三类：有真实观察的，换成原句并注明出处；只是一两句判别用语的，作为规则定义保留；无观察的长示例删除，保留规则文本并记案例缺口。

**迁移边界**：禁止自拟不等于删除所有例子。判别用语与规则定义不可分时保留；长示例须有来源。

来源：同上 F3。

## 6. 同一机制在热路径重复出现

**观察**：一条"普通操作详略"机制在写作者每次必读的两份文件中以不同措辞出现八到十次，附五个示例；这些重复是前述逐轮加规则留下的。行为对照已表明重复不提高遵循率。

**决定性差异**：重复分散执行者对知情、因果、声音等其他决定的注意，每次修改还要同步多处。修复是完整定义只留在拥有该职责的一处，调用方保留一句短锚，设计侧判据只留在设计阶段的一处字段说明。

**迁移边界**：短锚与完整定义各有功能；去重不是把热路径关键约束删到执行者读不到。

来源：同上 F5。

## 7. 上游写死决定，下游层层放大

**观察**：场景设计把三个人物"分别承认"写成不可逆动作并预排逐人责任框；角色视图把作者的这项安排投影为人物已有认识；隔离的角色行动候选据此扩写为划框、落名、认责的完整流程；写作者近逐字采用；场景审阅按"与设计一致"放行。首次盲审失败出现在写作者的输入层，而非正文。

**决定性差异**：失真从上游的具体安排开始，经多层交接被重复确认而不是修正。下游名义上拥有合并、替换、舍弃的权限，实际未行使，因为上游给的是成品式指令。修复位置在设计粒度（只保留必须成立的状态变化与因果，不预写逐人话轮）和投影规则（不把作者安排写成人物已知），而不是再给写作者加规则。

**迁移边界**：判断上游是否越界的测试是：删掉这条具体安排、只留结果要求，下游能否凭现场信息作出同样好或更好的选择。真正需要固定顺序的专业流程仍可保留。

来源：`MUSE/docs/Level_2_architecture/pipeline/2026-09-03-流程交付物僵化.md` §2.2、§3；`MUSE/docs/Level_3_implementation/skills-audit/2026-10-02-skills-system-insight-analysis.md` §2.3。

## 8. 重复 owner 与事后参考

**观察**：同一设计阶段的参考查询出现两条路径：编排者先派一个研究子任务查询并产出候选文件，阶段负责人随后再次查询同一参考源。产物时间顺序显示多个阶段的参考文件晚于对应设计定稿，最终大纲又晚于下游场景卡与初稿。另有内容相同的别名产物无人消费。

**决定性差异**：升级目标只要求"设计证据在负责人定稿前到达"，第二个研究角色、候选文件与二次查询是实现阶段自行加入的。晚到的参考无法指导已经完成的设计，形成表演式参考；晚改的上游又使下游输入可能不一致。裁决是参考只保留一个 owner，参考必须在对应设计定稿前完成，停止事后回写。

**迁移边界**：流程膨胀的可识别形态：同一决定有两个 owner、同一信息有两份产物、参考晚于决定、无人消费的别名文件。固定的 Phase 6 契约步骤不计入膨胀。

来源：`MUSE/docs/Level_2_architecture/pipeline/2026-08-30-Query183生成对照与流程膨胀.md` §4.4、§5、§6。

## 9. 隐含约束被实现为固定章节

**观察**：报告生成要求"客户输入应改变任务定义、方案比较与建议"。实现者新增固定章节"客户输入与决策边界"，只要输入非空就自动展示输入表，并用文字匹配测试强制该章节存在。用户团队认为该章节多余。

**决定性差异**："事实应改变论证"被替换成"报告应展示已读取事实"。章节证明系统执行过一个步骤，没有推进读者的决策。修复是删除固定章节、注入逻辑与强制测试，把客户事实投射到它实际改变的论点、条件与行动中；只有客户要求核对输入、输入本身是待决事项或协议要求独立确认时，才单独建立确认内容。

**迁移边界**：判据是"删掉该章节后，读者是否失去一项实际决策信息"。必要的输入清单、假设表、审计附件仍可保留，条件是它们有独立的读者任务。
