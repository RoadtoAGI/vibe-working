# 负例：从展示形式推导需求

适用于从模板、视觉丰富度或流程完整性推导新增模块，以及检查实现方案是否仍服务用户目标。案例来自真实产物与用户裁决，经用户于 2026-09-22 授权用于增强本 skill。

## 情境与观察

一份社媒合作方案已经提供五个备选合作包，各包说明资源、内容任务、数量及执行条件。后续视觉实施方案把“五包之间没有按方向的比较”列为缺口，新增“五包内容方向分布”矩阵，按方向汇总各包内容条数。

执行者完成该任务，并检查数量汇总、条件状态、HTML/Markdown 输出和窄屏显示。之后用户反馈团队认为这部分多余，要求删除。既有检查证明了矩阵符合设计；记录中没有说明客户为什么需要这个比较维度、现有选包与执行明细为何不足。

## 决定性差异

失误发生在把“尚无某种展示形式”直接提升为产品缺口。该假设进入实施任务和验收断言后，执行者沿这些要求完成检查，最初的必要性判断未被重新核对。后续测试通过没有增加支持业务必要性的证据。

提出或执行类似方案时，回到消费者要理解、选择或采取的行动，判断新增模块带来的信息或操作收益，以及现有载体是否已经足够。本例中，用户裁定删除独立矩阵，各包继续保留自己的方向与数量。

## 迁移边界

本例支持检查设计依据，不能推出“汇总就是重复”或“用户没逐项点名就不能新增”。复用明细的概览若能减少查找、心算或比较成本，可以成立；新增功能有明确使用情境或必要机制依据时，也可以在授权目标内实现。是否新增独立模块由其净收益决定，无需为每次布局调整另建审批、量化指标或证明文档。

用户对本报告的裁决在本报告生效；本文记录的通用机制是必要性依据在方案、实现与验收间被遗漏。案例尚未用于独立的跨任务效果比较，不据此声称能稳定减少多余功能。
